# NIGHT SIGNAL 要求台帳

更新日: 2026-07-16

## ビジョン

利用者が大量のWeb、公式発表、報道、専門媒体、データ、YouTube、X、
Facebook、Instagram、TikTokを毎日巡回しなくても、設定テーマで起きた有用な
変化を広く把握でき、どの項目を詳しく読むかを自分で決められるようにする。

「重要更新」は上位数件という意味ではない。設定テーマに関係する、新規または
実質的な変化を指す。掲載件数を減らすための上限は設けない。一方、類似情報、既知情報の
言い換え、定例更新、低重要度情報は掲載前に除外し、件数そのものを網羅性の指標にしない。

## 必須要求

### 探索

- 全watch topicを、登録ソース確認と未登録情報の探索の両方で確認する。
- 日本語と英語を標準とし、地域テーマでは現地語の検索も行う。
- Web、YouTube、X、Facebook、Instagram、TikTokの公開情報を、追加費用なしで
  到達できる範囲まで確認する。
- 公式、主要報道、専門媒体、データ、現地媒体、SNS、動画の一つだけで完了扱いに
  しない。
- 検索結果件数やURL到達数ではなく、実質的変化が本文まで解決されたかを測る。
- 同一事象の転載は統合する。決定、実行、結果など異なる進展は消さない。
- 件数上限、末尾切捨て、カテゴリ単位の少数選抜で情報を落とさない。

### 本文と根拠

- 見出し、索引、トップページ、検索抜粋を記事本文と同一視しない。本文解決を先に
  試み、解決できない時は、見出しだけで題名と別の具体的事実を支えられる場合に限り、
  見出し根拠として同じEditorへ渡す。推測で本文相当へ膨らませない。
- 配信集約URLではなく、可能な限り配信元の原文へ解決する。
- 公開リンクは、読者が内容を確認できる原文URLにする。
- 本文が取れない重要候補は別検索で解決を試みる。無関係なページへ接続しない。
- PDF、表、グラフ、画像に重要事実がある場合だけ、その内容を抽出対象にする。
  毎回画像や図を追加しない。
- 出典とカテゴリ主体の関係を確認し、Honda欄へ無関係な三菱情報を入れるような
  カテゴリ混入を許さない。

### 掲載と要約

- 変化または新規項目があり、根拠を確認できた場合は原則掲載する。
- 題名と、更新を理解するために必要十分な事実を表示する。
- 主体が一般に知られていない場合は、参照元にある役割・事業を必要な範囲で残す。
- 主体、変化、対象、仕組み、固有名、数値、日付、条件、理由、結果のうち、
  記事理解に必要な情報を落とさない。必要なら要約は長くてよい。
- 題名の言い換え、同じ事実の反復、一般論、常識、媒体名、確認作業、根拠のない
  重要性・影響、定型的な未確定点を加えない。
- 参照元が薄い場合は短いままにする。最低文字数を満たすために膨らませない。
- 最近公開された分析が過去の事実を扱う場合は、今回新しく検証・分析された内容と
  帰結がなければ掲載しない。
- 四半期決算、通期決算、本決算、最終決算は定例であることを理由に除外せず、実績発表を
  イベントとしてEditorへ渡す。上方・下方修正、黒字転換・赤字転落、初配当・増減配、
  過去最高、大幅な市況変動も直前号からの重要な差分として残す。除外するのは決算・指標の
  予告だけの記事、実績を含まない株価コメント、小動きだけの時点速報とする。
- 記事公開日と出来事の日付を混同しない。
- 公開画面には従来形式の重要更新だけを出す。候補、確認情報、参考情報、作業履歴、
  内部の除外理由は表示しない。

### 運用

- JST当日号を19:00までに固定URLへ公開する。
- 19:00以降の通常情報は翌日号へ送り、緊急性と影響度が特に高い変化だけ当日追記する。
- 最終収集開始可能時刻は固定値を先に決めず、19:00からend-to-end処理上限と安全余裕を
  引いて算出する。定期起動の予定時刻ではなく実際の開始時刻で実行可否を判定する。
- 予定より早い定期起動は収集・AI処理を行わず、期限後の定期起動も無駄な処理をせず失敗を
  明示する。定期公開は過去のEvidenceを鮮度確認の代用にしない。
- 承認待ちで停止しない。
- 前日号を当日号として再表示しない。前日号の処理が日付を跨いだ場合は、翌日の最終収集
  開始時刻より前に限り、同じ前日Evidenceと前日の日付表示のまま復旧公開できる。当日号の
  収集開始後は前日号をrootへ出さず、異なる日付のEvidenceを当日号へ流用しない。
- repositoryには公開中の号と直前3号を残す。直前号を最優先、さらに前2号を補助履歴として
  新規性検証に使い、公開archiveから
  読めるようにする。全監査合格後に4号より古いstate、sample HTML、dated siteを削除する。
- GitHub ActionsはEvidence収集だけ、ChatGPT Plusに含まれるCodex automationは編集、
  検証、commit、公開だけを担当し、同じ段階を実行する第二ownerを作らない。
- 公開失敗時に収集やAI編集を無条件で繰り返さず、入力が同じ完了段階を再利用する。
- ChatGPT Plus以外の有料API、GitHub Models、Copilot creditを日次経路で使用しない。

### 品質と効率

- CollectorはEvidenceを取得し、Editorだけが事象統合、採否、要約を行う。
- Validatorは拒否だけを行い、文章を後段で補修しない。
- 同一事象の決定的なgrouping後、採否と要約をChatGPT Plus内の一回のcompact reviewで
  行う。全eventを渡し、分析、表・グラフ、高数値密度のeventには`quality_route`を付けて
  同じGPT-5.6 Terra review内で慎重に照合する。件数上限や下位modelへの品質切下げは行わない。
- 失敗時はValidatorが示したrequest/eventだけを修正し、合格済みeventを再生成しない。
- 推論量、モデル、再検索、再検査は、代表評価で品質向上が確認できる時だけ増やす。
- 日次は境界検査だけとし、全故障simulationとモデル比較は設計変更時に行う。
- 新技術はEvidence取得手段またはEditorの置換候補として比較し、採用後に旧経路を
  恒久的に残さない。
- 公式latest-model情報は週次だけ確認する。新modelが利用可能になった時だけ代表Evidenceで
  網羅性、抽出精度、要約品質、tokenを比較し、最新という理由だけで本番modelを自動変更しない。

## 過去トラの再現クラス

個別ニュース名を本番の条件分岐へ追加しない。次の事例は、同じ失敗型を再現する
評価データとして扱う。

- 網羅性不足: ブレックスのアリーナ、SpaceXとCursor、OpenAIの日本広告・人材、
  Honda/F1、高市首相とモディ首相の経済安全保障などを探索できなかった。
- 空白・過少掲載: 日本経済などのカテゴリが空白、または全体件数が不自然に少なかった。
- カテゴリ混入: Honda欄へ三菱など別主体の情報が入った。
- 本文未取得: Honda月次実績、Sarashina3、ベトナム原発、FPT提携など、原文に情報が
  あるのに見出し程度へ縮んだ。
- 水増し: 同じ事実を題名、概要、確認事実、重要性へ言い換えて反復した。
- 一般論: 「投資家の意思決定に影響する」「今後の確認が必要」など、根拠のない定型文を
  追加した。
- 新規性不明: SoftBankの過去利益などを、今回取り上げる理由なしで再掲した。
- 抽出ノイズ: Billboardのナビゲーション、PDFの連絡先、ページ軸、媒体情報を本文として
  掲載した。
- 重複: SoftBankの同一投資、F1の同一イベントなどを複数カードへ分けた。
- 誤った根拠: 見出しだけ、検索結果だけ、無関係な本文、集約URLを根拠にした。
- 表示構造の増殖: 候補、確認情報、参考情報を公開画面へ追加した。
- 運用停止: 承認待ち、日付跨ぎ、再実行、古い号の再表示により当日公開できなかった。
- トークン浪費: 同じ収集・編集・検査を繰り返し、単純案件にも高品質modelを使った。

## 合格条件

- 全カテゴリ、全watch topic、全必須探索チャネルの実行結果がある。
- 見つかった実質的変化が、件数都合で捨てられていない。
- 掲載した各要約文に原文の根拠があり、必要な固有情報を保持している。
- 原文が豊富な代表事例で必要事実の欠落がなく、薄い代表事例で水増しがない。
- 同一事象の重複、カテゴリ混入、抽出ノイズ、一般論、題名反復がない。
- 原文リンクが配信元へ到達する。
- 19:00までに当日号のroot URLとdated URLが一致して公開される。
- 品質を維持した上で、model call、入力token、再実行、処理時間が最小化されている。
